# clover-project-cr 步骤文档（唯一总纲）

> **本项目**：1:1 复刻《皇室战争》（Clash Royale）**核心对局逻辑**的**联机**卡牌对战游戏。
> 形态 = **联机**（闸门 0 已判；见 `策划/策划案/皇室战争参考规格.md` §0）。
> **本文件是各 agent 接口对齐的唯一依据。** agent 之间不许私自改契约；发现契约有问题 → 先回报主 agent。

---

## 0. 目标与验收

**一句话验收标准**：打开 Unity 工程点 Play → 启动画面 → 主菜单 → 注册/登录 → 设昵称 → 主菜单可进
「卡组编辑 / 房间列表 / 人机对战 / 设置」→ 建房或建房列表加入或直接打 AI → 读条进图 →
在 18×32 竞技场上用 8 张卡组（60 张卡池）拖放出牌、圣水按 1x/2x/3x 回复、兵种过桥进攻、塔被摧毁、3 分钟 + 2 分钟加时 →
三冠/比塔/比血判胜负 → 结算 → 再来一局或回主菜单（第二次进入无残留）。

**必须做到（缺一不可）**：
- ① 启动与菜单链路 ② 对局全部内容 ③ 游戏内流程（暂停/结算/回主菜单）
- 用户点名：**60 张卡** / **不做养成** / **人机 PK（训练场入口 + 房间 AI 补位）** / **创建房间 + 房间列表加入** / **联网**
- 数值/几何/规则逐条对齐 `策划/策划案/皇室战争参考规格.md`（每条都有出处）

> ⚠️ **表名必须英文 + `_cs` 后缀**（`card_cs` / `unit_cs` / `spell_cs`）：Go 只把「首字符为大写 ASCII 字母」
> 视为导出，中文表名会让打表产物在 `table` 包外**完全不可用**（实测 5 处 `cannot refer to unexported field`）。
> 访问器：**`table.Default.Card.Get(id)` / `table.Default.Unit.Get(id)` / `table.Default.Spell.Get(id)`**。
> tsv 落点 `server/game/table/tsv/{card,unit,spell}.tsv`；打表 `tools/table.ps1 -Force`。

**数值唯一出处**：`<根>/原版资源/cr-api-data/docs/json/`（官方静态数据）+
`<根>/原版资源/cr-sim/reference/anchors.json`（手工核验锚点）。
**统一取「锦标赛标准 = 11 级 = 逐级数组索引 10」**（口径交叉验证见参考规格 §4）。

**铁律**：⛔ 数值一律不得硬编码进 Go/C# 代码；运行时只走打表产物（服务端 `table.Default.Xxx.Get(id)` / 客户端 `Tables.Default.Xxx.Get(id)`）。

## 4. 关键契约（★ 唯一依据，不许私自改）

### 4.1 消息号（★ 手工维护，不引入代码生成）

> 引擎占 `[1,10000]`（`proto.InternalMsgMax = 10000`）。业务 C2S **必须 ≥ 10001**（启动期校验，误用 panic）。
> **两端同名同值、同时改。** 服务端真身 = `server/game/def/{msg.go,push.go}`；客户端镜像 = `client/Assets/Scripts/Def/MsgDef.cs`。
> **回包不占消息号**（引擎按 `requestID` 配对，回包帧 msgID 恒为 0）—— 只定义**回包结构体**。

**C2S（`server/game/def/msg.go` / 客户端 `MsgDef`）**

### 4.2 `战斗单位_cs` 字段

来源列（官方 JSON 字段名 → 配表列名）：`hitpoints`→`hp`、`damage`→`damage`、`hit_speed`→`hit_speed_ms`、
`load_time`→`load_time_ms`、`speed`→`speed`（格/分钟）、`range`→`range_mt`（milli-tile）、
`sight_range`→`sight_mt`、`deploy_time`→`deploy_ms`、`collision_radius`→`radius_mt`、`mass`→`mass`、
`attacks_air`→`atk_air`、`attacks_ground`→`atk_ground`、`target_only_buildings`→`only_buildings`、
`projectile`→`projectile_key`、`spawn_character`→`death_spawn_key`、`spawn_number`→`death_spawn_n`、
`target_only_towers`→`only_towers`、`target_only_troops`→`only_troops`、`life_time`→`life_ms`。

补充列（本项目自定，取值自官方同族字段）：`kind`（0=部队 1=建筑 2=塔 3=投射物）、`name_cn`、`sprite_dir`、
`aoe_radius_mt`、`death_aoe_radius_mt`、`death_damage`、`summon_key`、`summon_n`、`summon_radius_mt`、
`spawn_interval_ms`、`spawn_limit`。
投射物**不是**本表的补充列：投射物是**独立行**（`kind=3`），其弹道速度 / 弹体半径就是该行的
`speed` / `radius_mt`（列注释：投射物行为弹道速度 / 弹体半径）。协议下发的 `CardInfo.proj_speed`
即取自「该卡战斗本体 `projectile_key` 指向的那一行」的 `speed`（格/分钟），
出处 = 官方 `cards_stats_projectile.json` 的 `speed`。

### 4.3 `法术_cs` 字段

`id` / `key` / `name_cn` / `elixir` / `rarity` / `radius_mt` / `instant_damage` / `crown_damage` /

### 4.5 服务端模块边界（★ 依赖单向）

```
server/game/
├── def/       消息号 + 协议结构体（无业务逻辑，无引擎依赖）
├── datadef/   数据 schema（player 档案）+ 结构体
├── table/     ★ 打表产物（自动生成，不许手改）
├── core/      ★ 对局内核：纯 Go，**不许 import 任何 clover-server-engine 包**
│              可离线 `go test ./game/core/...`（秒级断言，不许进 Play/起服）
└── logic/     引擎 handler：只做「取参 → 调 core → 回包/推送」，不许写玩法规则
```

**铁律**：`core/` 是对局逻辑的**唯一实现处**；`logic/` 不许出现伤害/速度/射程等数值或规则分支。

### 4.6 客户端模块边界

```
client/Assets/Scripts/
├── Def/          MsgDef.cs（消息号唯一处）+ ProtoDef.cs（协议结构体）
├── Core/         ClientConfig.cs / Events.cs（事件名常量）/ GameConst.cs
├── Module/       Flow（流程编排）/ Room（房间）/ Battle（对局）/ Deck（卡组）/ Settings
├── UI/Panels/    各站点面板（UIPanel 子类，只发/收事件，**不许 using Module**）
├── View/         战斗表现（竞技场/单位/血条/卡面/特效）
└── App/Bootstrap.cs   唯一组装点（≤200 行）
```
