## 素材身份的**权威索引**（取自 A 本体的 `.sc` 显式数据，不是看图猜）

上表给出的是「素材从哪来」；下面两份文档给出的是「**哪一张帧是哪个控件**」——
这个问题的权威来源是 **Clash Royale 2.1.5 APK 的 `.sc`**（QuickBMS 解密后的明文，持久副本 `原版资源/sc/*_v215.sc`，
来源说明见 `原版资源/sc/来源说明.md`）。两份文档共同覆盖全部落地图元：

| 文档 | 管什么 | 复跑入口 |
|---|---|---|
| `策划/原版UI素材名称索引.md` | 每个 `.sc` 的 **export 表**（→ clip → shapeID），即「每个 shape 被哪些 clip 显式引用」 ⇒ 原版的**语义名** | `tools/probes/ui-sc-index.py` |
| `策划/原版UI素材名称索引.md` + `策划/原版UI图元更正表.md` | **65 个落地图元逐条判定**（命中 / 不符 / 无法判定 + 建议），即「我们的键名对不对」 | `tools/probes/ui-sc-index.py`（生成更正表） |
| `策划/原版UI布局坐标.md` | `.sc` 的 **`08` 放置矩阵 + `0c` 三元组**解出的**坐标/尺寸**（相对值已与截图像素互证到 0.8%；绝对值仍未解出） | `tools/probes/sc-layout.py` |
| `策划/战斗HUD素材索引.md` | **战斗 HUD 层**（圣水条 / 手牌槽 / 冠数 / 倒计时 / 暂停按钮）的 `0c` **具名子元件** → 帧号（HUD 不在独立 `.sc` 里，而在 `ui.sc` 的 `HUD_*` export 内部） | `python .ai-tmp/test/aa2-resolve.py ui:1091 ui:1080 …`（解析器 = `tools/probes/sc-anim-index.py`） |

> ⛔ 业务代码**不许**写这些路径字面量：帧号一律经 `client/Assets/Scripts/Core/ResPaths.cs` 的键取，
> 键 ↔ 磁盘文件 ↔ 落地脚本 三向一致由 `tools/probes/check-ui-keys.ps1` 与 `tools/probes/copy-ui-assets.py` 把关。
> 逐项对照（原版值 / 我们的值 / 差值 0）见 `策划/对照表.md`；未消化的差异见 `策划/验收表.md` 的「允许的差异」。
