## 四条硬规则

1. 新设施先登记再写代码：新增消息号 / handler / 面板 / 管理器 / 配表 → **同步更新 `registry.md`**。
2. 只记本项目特有的东西，通用规则**不许**抄进来（抄了必然两边漂移）。
3. ⛔ **本文件只许对全局 skill "加严"，不许"放宽"**。特别注意这几条不许被"项目化"放宽：
   临时文件位置（全局 §1.8：一律 `<项目根>/.ai-tmp/`，⛔ 不许 `client/_dev/`、项目根、`tools/`）；
   交付闸门（§2）；收尾机械自检（§1.11）；引擎能力优先（§6）。
4. **子 agent 不会自动继承 skill**：派子 agent 时任务书必须写明「怎么拿到本 skill」——
   先读 `<项目根>/tools/ai-skill/SKILL.md`，再给全局 `clover-engine` 与 `unity-cli` 的入口路径。

## 本项目专属的五条硬规则

5. **数值一律走配表**：⛔ 不许把卡牌/单位/塔的数值硬编码进 Go 或 C#。
   运行时只走打表产物（服务端 `table.Default.Xxx.Get(id)` / 客户端 `Tables.Default.Xxx.Get(id)`）。
   配表源表在 `策划/数值文档/`，**表名必须带 `_cs` 后缀**。
6. **`server/game/core/` 必须保持"纯 Go、零引擎依赖"**：⛔ 不许 import 任何 `clover-server-engine/...`。
   它是唯一能**离线秒级断言**的地方（`go test ./game/core/...`），是所有玩法规则的正确性来源。
7. **玩法规则的唯一实现处是 `game/core/`**：`game/logic/` 只做「取参 → 调 core → 回包/推送」，
   ⛔ 不许在 handler 里写伤害/速度/射程/胜负等规则分支。
8. **消息号手工维护**（⛔ 不引入代码生成）：两端同名同值、同一批改动。
   客户端唯一处 `client/Assets/Scripts/Def/MsgDef.cs`；服务端 `server/game/def/{msg,push}.go`。
   ⛔ 业务脚本里出现裸消息号字面量一律算错。
9. **几何/数值的唯一出处**是 `策划/策划案/皇室战争参考规格.md`（含逐条文件级出处）。
   写任何数值前先在那里找；找不到 ⇒ **不许编**，回报主 agent。
