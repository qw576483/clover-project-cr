| 整屏页 vs 弹窗（#3） | ⛔ 不能 | 站点/层级契约（`DeckEditPanel.Layer => Popup`）不是本片权限 |

## 四、返工记录（本片自己抓到的缺陷，按"改完重截"处理）

1. **卡组屏一张真卡面都出不来（已修）**：第一次采集的审计里 `Card0Art sprite=NULL color=(0.06,0.09,0.15,0.96)`
   （= 底色块），控制台 `[Resource] 加载回调异常（Sprites/Cards/ui_spells_out/frame_022）:
   Could not create sprite (98, 251, 197, 251) from a 403x377 texture`。
   根因 = `DeckEditPanel.ArtBboxY = 126`（按"Sprite.rect 左下原点、素材未裁剪"推的）⇒ 裁剪区**越出纹理**，
   `Sprite.Create` 抛异常、回调不返回。实测这些帧的 `sprite.rect.y` 已是 125 ⇒ **与 `HudPanel` 同口径取 0** 才对。
   → 改 `ArtBboxY = 0`，重编译、**重进 Play 重采**（截图 + 审计均晚于该修复）。
2. **已选槽位的卡面出画布 5.5px（已修）**：审计 `ASSERT offCanvasNodes=1 FAIL Slot0Art(-6,337)-(183,576)`。
   根因 = 卡面尺寸**恒用** `ArtW/ArtH = 188×239`（按卡池格宽 206 定的），而槽位宽只有 96。
   → 改为按格宽派生 `artW = size.x − 18`（卡池格 206−18=188 与原值一致；槽位 96−18=78）。
3. **卡池标签写「共 0 张」（已修）**：`OnPoolLoaded` 没有刷新页签行，而 `OnOpen` 里的 `RefreshPageLabel`
   跑在卡池到达**之前** ⇒ 画着 60 张卡却写"共 0 张"（截图可见的错数）。→ `OnPoolLoaded` 里补一行 `RefreshPageLabel()`。

> 三处修复都只动 `client/Assets/Scripts/UI/Panels/DeckEditPanel.cs`（本片范围内）；修后**重采**的
> `.ai-tmp/screenshots/V4-卡组编辑.png` + `.ai-tmp/test/v4-audit-step12-DeckBox.txt` 是当前有效证据。
